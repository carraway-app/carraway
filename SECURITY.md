# Security policy

## Reporting a vulnerability

Use [GitHub Private Vulnerability Reporting](https://github.com/carraway-app/carraway/security/advisories/new) if the form is available, or email [security@carraway.vc](mailto:security@carraway.vc). Keep vulnerability details out of public issues and pull requests.

Include the affected version or commit, the deployment method and relevant settings, the impact, and enough detail to verify the report using fictional data. Mention any known public disclosure. Remove credentials and personal data from logs, screenshots, and other attachments.

## Supported versions

Security fixes are provided for the latest published version of the core and its container image. Fixes ship in a new release. See the [self-hosting guide](deploy/README.en.md) for update instructions.

## Response and disclosure

Rehlytics aims to acknowledge reports and share an initial assessment as soon as possible. The timing of assessment and fixes depends on severity, complexity, and availability. Critical issues are prioritized. Rehlytics will coordinate disclosure with the reporter, normally after a fix is available, and can credit the reporter on request.

## Scope and research guidelines

This policy covers the public Carraway source code, its deployment files, and the container image built from this repository. Report issues specific to third-party services or independently operated instances to the relevant operator.

Test only on systems you own or have explicit permission to assess. Protect other people's data, avoid service disruption, and allow reasonable time for a fix before sharing details publicly. Rehlytics will refrain from pursuing legal action over good-faith research conducted within these guidelines.
